# 主要コード解説

この資料は、本リポジトリに掲載した主要コードの目的、問題の原因、解決方法を説明します。

## 1. WerewolfFormComponent

### 実装内容

人型から人狼への変身と解除を管理し、Mesh、Animation Blueprint、Capsule、移動性能を切り替えます。

### 担当範囲

変身処理全般は本人申告の担当範囲です。`WerewolfFormComponent.cpp/.h` はファイル責務も一致するため、本人作成候補としました。

### 問題と原因特定

変身後に人狼が浮く、または床へ埋まる問題がありました。Capsule Half Height変更前後の底面位置、参照Mesh Bounds、AnimInstance適用後の実Bounds、左右の足Bone位置を比較すると、体格差と尻尾を含むBoundsが原因だと切り分けられます。

### 解決と改善

Capsule底面を維持してActorを補正し、AnimInstance適用後は足Boneを基準にMesh位置を再補正します。解除時は最初に保存した人型値へ戻すため、繰り返し変身による累積ずれを防ぎます。

## 2. EnemyDecisionComponent

### 実装内容

ボスの近接、銃、レーザーの候補を独立して採点し、最大Scoreの攻撃形式を選びます。

### 問題と原因特定

条件分岐の順番だけで攻撃を決めると、条件追加時に以前の分岐が到達不能になる問題があります。攻撃条件と選択結果の関係を関数単位で確認できるように分けました。

### 解決と改善

距離、残弾率、プレイヤー状態、味方数等を各Scoreへ加減算します。候補評価と実行を分けたことで、条件追加の影響範囲が読みやすくなりました。

### 現状の制約

攻撃選択理由を出力する実行時ログは現行版にありません。面接ではログ機能を実装済みとは説明しません。

## 3. EnemyAIController / BTService_EnemyContext

### 実装内容

AI Perceptionの刺激を受け取り、Target Actor、最終確認位置、視認状態を保持します。Serviceは距離、射線、攻撃可能状態等をBlackboardへ同期します。

### 問題と原因特定

敵が目の前のプレイヤーへ反応しない、見失った後に停止する場合、知覚、ControllerのTarget、Blackboard、Taskのどこで情報が途切れたかを分けて確認する必要があります。

### 解決と改善

知覚、記憶、条件更新、行動実行の責務を分け、最後に確認した位置への捜索と戦闘空間内の認識補助を用意しました。

## 4. EnemyBehaviorTasks

### 実装内容

追跡、攻撃、捜索、巡回、近距離・遠距離の陣形、遮蔽物への移動をBehavior Tree Taskとして実装します。

### 問題と原因特定

巡回地点が近すぎる、直前と同じ場所を選ぶ、敵同士が同一点へ集まる問題がありました。候補地点と現在地、前回地点、味方位置の距離を別々に検査します。

### 解決と改善

NavMesh上の候補へ最小移動距離、前回地点との距離、味方との距離を設け、複数回候補を探索します。戦闘時は近距離と遠距離で異なる配置を選びます。

## 追加掲載候補: EnemyCoverComponent

### 実装内容

遠距離敵が利用する遮蔽物候補と横回避位置を評価します。

### 問題と原因特定

最短距離だけで遮蔽物を選ぶと、プレイヤーから隠れない位置、到達不能な位置、味方と重なる位置が選ばれます。

### 解決と改善

NavMeshへの投影、経路、遮蔽物の遮断、プレイヤーとの適正距離、移動距離、味方との角度をScoreへまとめ、最も有効な候補を選択します。

最初の公開では主要5件へ絞り、採用担当者へ追加説明が必要な場合に掲載する候補です。
